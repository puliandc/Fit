## 当前应用对训练计划 JSON 的真实支持

你输出的训练计划会被当前版本 Fit 应用直接解析。请遵守这些实际规则：

1. 必填顶层字段只有 `训练计划名称` 和 `练习项目`
2. 每个练习项目必填 `练习名称` 和 `组数设置`
3. 每组必填 `目标次数`、`目标重量`
4. `目标重量` 支持整数和小数，例如 `40`、`17.5`
5. `休息时间` 可省略，省略时应用默认 `90`
6. `备注` 可选；如果提供：
   - 会显示在训练中的动作卡片
   - 会作为“动作完成”弹窗的默认备注
   - 会在训练日志里与用户手填备注合并
7. `组数类型` 当前不会改变应用执行逻辑，但建议保留，方便阅读
8. 任意一组字段类型错误会导致整份计划导入失败，不会静默跳过

## 超级组规则

当前应用已经支持“按顺序执行的超级组”，但没有单独的超级组数据模型。你必须按下面方式表达：

1. 用 `练习名称` 说明这是一个超级组，例如：
   - `超级组 A：胸背对抗 (连续做完A1+A2再休息)`
2. 在同一个 `组数设置` 数组里，按真实执行顺序展开：
   - `A1`
   - `A2`
   - `A1`
   - `A2`
3. 用每组的 `备注` 标注 `A1` / `A2` 和动作提示
4. 如果 A1 做完后应立即接 A2，则 A1 的 `休息时间` 写 `0`
5. 不要指望应用根据 `组数类型` 自动理解超级组；真正的执行语义来自“数组顺序 + 休息时间”

## 你的任务

读取我提供的训练日志，分析最近 2-4 周的训练进展和疲劳情况。
根据训练周期进展，自动判断“今天”应该训练的内容（以全身训练为主）。

输出完整的一次训练计划，包括：动作、组数、次数、重量、是否热身、每组休息时间、每组备注。

## 渐进超负荷与退阶规则

- 原则：优先保证动作质量与关节安全，在此基础上进行渐进超负荷
- 每个动作使用“次数区间 + 重量进阶”逻辑，例如：
  - 复合动作：3-5 组，6-10 次
  - 单关节/小肌群：2-4 组，10-15 次

进阶逻辑：

1. 若最近两次训练在同一重量下，大部分工作组都达到或接近次数上限，且日志中未出现异常疲劳或疼痛：
   - 上肢动作：`+2.5kg`
   - 下肢动作：`+2.5kg` 到 `+5kg`
2. 若未达到目标次数：
   - 先在同一重量下提升次数，不要立刻退阶
   - 若连续 2-3 次训练明显未达标，再退阶 `2.5%` 到 `5%`
3. 微周期逻辑：
   - 第 1 次：维持重量，争取多 1-2 次或更稳的动作质量
   - 第 2 次：在表现良好前提下加重量

## 全身训练与动作选择

1. 每次尽量覆盖全身，但总工作组数控制在 `15-22` 组
2. 每次至少包含 `1-2` 个复合动作，可从以下选择：
   - 杠铃肩推、杠铃深蹲、硬拉、卧推、引体向上
3. 其他动作可从以下选择，也可以在合理时加入新动作（每次新增不超过 1 个）：
   - 坐姿 V 把划船、高位下拉、哑铃俯身飞鸟、龙门架绳索面拉
   - 哑铃弯举、双杠臂屈伸、龙门架夹胸、哑铃侧平举、哑铃颈后臂屈伸
   - 弓步蹲、龙门架髋外展、龙门架跪姿卷腹、悬垂举腿
4. 可以使用超级组，但只在确实有训练价值时使用，不要为了形式硬加
5. 避免同一节训练中过度堆叠同一关节压力

## 热身规则

1. 对所有大重量/复合动作（深蹲、硬拉、卧推、引体、杠铃肩推）：
   - 若工作重量 `< 60kg`：
     - 至少 1 组热身：`40%` 工作重量，`8-10` 次
   - 若工作重量 `>= 60kg`：
     - 2-3 组热身，例如：
       - `40% x 8-10`
       - `60-70% x 3-5`
2. 小重量/单关节动作可以不单独写热身组

## 休息时间规则

- 热身组：`60`
- 复合动作：`120`
- 其他动作：`90`
- 下一组重量变化：`+30`
- 动作最后一组：`+60`

```text
if isWarmup:
    base = 60
else if isCompound:
    base = 120
else:
    base = 90

deltaWeight = 30 if nextSet.weight != currentSet.weight else 0
endOfExercise = 60 if isLastSet else 0

restTime = base + deltaWeight + endOfExercise
```
