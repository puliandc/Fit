# 训练计划 JSON 数据结构说明

本文档基于当前 `JSONWorkoutParser.swift` 的实际实现编写，描述当前版本 Fit 应用真正支持的训练计划格式。

## 核心结论

当前版本已经支持：

1. `目标重量` 使用整数或小数
2. 每组 `备注`
3. 超级组按顺序执行
4. 任意一组配置错误时整份计划导入失败

当前版本仍然不支持：

1. 基于 `组数类型` 的特殊执行逻辑
2. 独立的“超级组”数据模型
3. 基于外部字段的排序、ID、分组元数据

## 最小可用 JSON

```json
{
  "训练计划名称": "全身力量训练计划",
  "练习项目": [
    {
      "练习名称": "杠铃卧推",
      "组数设置": [
        {
          "组数类型": "正式组",
          "目标次数": 5,
          "目标重量": 45,
          "休息时间": 90,
          "备注": "下放稳定，胸部主动发力。"
        }
      ]
    }
  ]
}
```

## 字段支持情况

### 顶层字段

| 字段 | 类型 | 是否必填 | 当前处理方式 |
| --- | --- | --- | --- |
| `训练计划名称` | `String` | 是 | 实际解析 |
| `练习项目` | `Array` | 是 | 实际解析 |
| `日期` | `String` | 否 | 允许存在，但当前解析器忽略 |
| `饮食策略` | `String` | 否 | 允许存在，但当前解析器忽略 |
| 其他额外字段 | 任意 | 否 | 允许存在，但当前解析器忽略 |

### 练习项目字段

| 字段 | 类型 | 是否必填 | 当前处理方式 |
| --- | --- | --- | --- |
| `练习名称` | `String` | 是 | 实际解析 |
| `组数设置` | `Array` | 是 | 实际解析 |

### 组数设置字段

| 字段 | 类型 | 是否必填 | 当前处理方式 |
| --- | --- | --- | --- |
| `目标次数` | `Int` | 是 | 实际解析 |
| `目标重量` | `Int` 或 `Double` | 是 | 实际解析，最终转为 `Double` |
| `休息时间` | `Int` | 否 | 实际解析，缺省时默认 `90` |
| `备注` | `String` | 否 | 实际解析，写入 `ExerciseSet.notes` |
| `组数类型` | `String` | 否 | 当前忽略，仅供人类阅读 |

## 超级组的正确表达方式

当前应用并不会因为你写了 `组数类型: 超级组` 就自动理解超级组。

真正有效的表达方式是：

1. 用 `练习名称` 说明这是超级组
2. 在同一个 `组数设置` 数组中按真实执行顺序展开各组
3. 用每组 `备注` 标识 `A1` / `A2`
4. 把需要无缝衔接的组的 `休息时间` 写成 `0`

### 推荐示例

```json
{
  "练习名称": "超级组 A：胸背对抗 (连续做完A1+A2再休息)",
  "组数设置": [
    {
      "组数类型": "正式组",
      "目标次数": 10,
      "目标重量": 17.5,
      "休息时间": 0,
      "备注": "A1. 哑铃平板卧推 - 控制离心，到底拉伸。"
    },
    {
      "组数类型": "正式组",
      "目标次数": 12,
      "目标重量": 40,
      "休息时间": 90,
      "备注": "A2. 坐姿划船 - 挤压背部。"
    },
    {
      "组数类型": "正式组",
      "目标次数": 10,
      "目标重量": 17.5,
      "休息时间": 0,
      "备注": "A1. 保持重量，不掉次数。"
    },
    {
      "组数类型": "正式组",
      "目标次数": 12,
      "目标重量": 40,
      "休息时间": 90,
      "备注": "A2. 动作不要变形。"
    }
  ]
}
```

### 当前应用中的实际表现

这份计划导入后：

1. 应用会严格按数组顺序逐组执行
2. `休息时间 = 0` 的组后不会进入正常休息倒计时
3. UI 不会额外显示“这是超级组”
4. 训练中的备注卡片会显示当前组的 `备注`
5. “动作完成”弹窗会用当前组 `备注` 作为默认值
6. 导出的训练日志会把计划备注与用户备注合并

## 数据模型映射

导入后，JSON 会被扁平化为：

```text
训练计划 JSON
-> WorkoutPlan
-> [ExerciseSet]
```

对应模型：

```swift
struct WorkoutPlan {
    let id: UUID
    let name: String
    let duration: Int
    let exercises: [ExerciseSet]
}

struct ExerciseSet {
    let id: UUID
    let exercise: Exercise
    let targetReps: Int
    let targetWeight: Double
    let restTime: Int
    var notes: String?
}
```

## 错误处理规则

当前解析器会在这些情况下直接失败：

1. 不是合法 JSON
2. 顶层不是对象
3. 缺少 `训练计划名称`
4. 缺少 `练习项目`
5. 某个练习缺少 `练习名称`
6. 某个练习缺少 `组数设置`
7. `组数设置` 是空数组
8. 任意一组的 `目标次数` 不是整数
9. 任意一组缺少 `目标重量`
10. 任意一组的 `目标重量` 不是数字
11. 任意一组的 `休息时间` 不是整数
12. 任意一组的 `备注` 不是字符串

对应错误类型：

```swift
enum JSONParseError: LocalizedError {
    case invalidFormat
    case invalidStructure
    case missingPlanName
    case missingExercises
    case missingExerciseName(Int)
    case missingSetConfig(String)
    case invalidSetConfig(exerciseName: String, setIndex: Int, reason: String)
}
```

## AI 生成计划时的建议

1. 始终输出中文字段名
2. `目标次数` 只用整数
3. `目标重量` 可用整数或小数
4. 每组尽量写简洁备注，便于训练中直接阅读
5. 若使用超级组，靠顺序和 `休息时间` 表达，不要依赖 `组数类型`
6. 即便顶层包含 `日期`、`饮食策略`，也必须保留 `训练计划名称` 和 `练习项目`

## 常见错误示例

### 错误：重量写成字符串

```json
{
  "目标次数": 10,
  "目标重量": "40kg"
}
```

### 错误：备注写成非字符串

```json
{
  "目标次数": 10,
  "目标重量": 40,
  "备注": ["A1", "卧推"]
}
```

### 正确：重量为数字，备注为字符串

```json
{
  "目标次数": 10,
  "目标重量": 40,
  "备注": "A1. 卧推 - 控制离心。"
}
```
