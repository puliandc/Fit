# Fit iOS 应用设计模式文档

## 概述

Fit iOS 应用采用了多种设计模式来构建一个可维护、可扩展的架构。本文档详细说明了应用中使用的主要设计模式及其实现方式。

## 核心设计模式

### 1. MVVM (Model-View-ViewModel) 架构模式

#### 模式定义
MVVM 是一种分离用户界面 (UI) 与业务逻辑的架构模式，特别适合现代响应式框架如 SwiftUI。

#### 在 Fit 应用中的实现

**Model 层**
```swift
// 数据模型定义
struct Exercise: Identifiable, Codable, Hashable {
    let id: UUID
    let name: String
    let category: ExerciseCategory
    let muscleGroups: [MuscleGroup]
    // ...
}

struct WorkoutPlan: Identifiable, Codable, Hashable {
    let id: UUID
    let name: String
    let exercises: [ExerciseSet]
    // ...
}
```

**ViewModel 层**
```swift
class WorkoutViewModel: ObservableObject {
    @Published var currentExerciseIndex: Int = 0
    @Published var isExerciseActive: Bool = false
    @Published var completedSets: [CompletedSet] = []

    let workoutPlan: WorkoutPlan

    // 业务逻辑方法
    func startExercise() { ... }
    func completeExerciseWith(actualReps: Int, actualWeight: Double) { ... }
}
```

**View 层**
```swift
struct WorkoutScreen: View {
    @EnvironmentObject var workoutViewModel: WorkoutViewModel

    var body: some View {
        VStack {
            // UI 绑定到 ViewModel 状态
            Text(workoutViewModel.currentExercise.name)
            Button("完成") {
                workoutViewModel.completeExerciseWith(actualReps: reps, actualWeight: weight)
            }
        }
    }
}
```

**优势**
- **数据绑定**: 自动同步 UI 和数据状态
- **可测试性**: ViewModel 可以独立测试
- **关注点分离**: UI 逻辑与业务逻辑分离

### 2. 观察者模式 (Observer Pattern)

#### 模式定义
观察者模式定义了对象间的一对多依赖关系，当一个对象状态改变时，所有依赖它的对象都会收到通知。

#### 在 Fit 应用中的实现

**使用 SwiftUI 的响应式系统**
```swift
class NavigationManager: ObservableObject {
    @Published var currentScreen: AppScreen = .main
    @Published var presentedDialog: DialogType?
    @Published var currentWorkoutViewModel: WorkoutViewModel?
}

// View 自动订阅并响应状态变化
struct ContentView: View {
    @EnvironmentObject var navigationManager: NavigationManager

    var body: some View {
        // 当 navigationManager.currentScreen 改变时，自动重新渲染
        switch navigationManager.currentScreen {
        case .main:
            MainScreen()
        case .workout(let plan):
            WorkoutScreen(workoutPlan: plan)
        // ...
        }
    }
}
```

**自定义观察者实现**
```swift
// 训练进度观察
protocol WorkoutProgressObserver: AnyObject {
    func workoutProgressDidChange(_ progress: Double)
    func exerciseDidComplete(_ exercise: Exercise)
}

class WorkoutViewModel: ObservableObject {
    private var observers: [WeakReference<WorkoutProgressObserver>] = []

    func addObserver(_ observer: WorkoutProgressObserver) {
        observers.append(WeakReference(observer))
    }

    func notifyProgressChange() {
        observers.forEach { weakObserver in
            weakObserver.value?.workoutProgressDidChange(progress)
        }
    }
}
```

### 5. 策略模式 (Strategy Pattern)

#### 模式定义
定义一系列算法，把它们一个个封装起来，并且使它们可相互替换。

#### 在 Fit 应用中的实现

**文件解析策略**
```swift
protocol FileParsingStrategy {
    func parse(file: URL) throws -> WorkoutPlan
}

class JSONFileParsingStrategy: FileParsingStrategy {
    func parse(file: URL) throws -> WorkoutPlan {
        let data = try Data(contentsOf: file)
        return try JSONDecoder().decode(WorkoutPlan.self, from: data)
    }
}

class XMLFileParsingStrategy: FileParsingStrategy {
    func parse(file: URL) throws -> WorkoutPlan {
        // XML 解析逻辑
    }
}

class FileParser {
    private var strategy: FileParsingStrategy

    init(strategy: FileParsingStrategy) {
        self.strategy = strategy
    }

    func parse(file: URL) throws -> WorkoutPlan {
        return try strategy.parse(file: file)
    }
}
```

**训练计算策略**
```swift
protocol ProgressCalculationStrategy {
    func calculateProgress(completed: Int, total: Int) -> Double
    func calculateCaloriesBurned(sets: [CompletedSet]) -> Int
}

class StandardProgressStrategy: ProgressCalculationStrategy {
    func calculateProgress(completed: Int, total: Int) -> Double {
        guard total > 0 else { return 0.0 }
        return Double(completed) / Double(total)
    }

    func calculateCaloriesBurned(sets: [CompletedSet]) -> Int {
        return sets.reduce(0) { total, set in
            total + Int(set.actualReps * set.actualWeight * 0.1)
        }
    }
}
```

### 6. 建造者模式 (Builder Pattern)

#### 模式定义
将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。

#### 在 Fit 应用中的实现

**训练计划建造者**
```swift
class WorkoutPlanBuilder {
    private var name: String = ""
    private var description: String = ""
    private var category: WorkoutCategory = .fullBody
    private var difficulty: Difficulty = .beginner
    private var exercises: [ExerciseSet] = []

    func setName(_ name: String) -> WorkoutPlanBuilder {
        self.name = name
        return self
    }

    func setDescription(_ description: String) -> WorkoutPlanBuilder {
        self.description = description
        return self
    }

    func setCategory(_ category: WorkoutCategory) -> WorkoutPlanBuilder {
        self.category = category
        return self
    }

    func addExercise(_ exercise: Exercise, reps: Int, weight: Double) -> WorkoutPlanBuilder {
        let exerciseSet = ExerciseSet(
            exercise: exercise,
            targetReps: reps,
            targetWeight: weight
        )
        exercises.append(exerciseSet)
        return self
    }

    func build() -> WorkoutPlan {
        return WorkoutPlan(
            name: name,
            description: description,
            category: category,
            difficulty: difficulty,
            duration: calculateEstimatedDuration(),
            exercises: exercises,
            estimatedCalories: calculateEstimatedCalories()
        )
    }

    private func calculateEstimatedDuration() -> Int {
        return exercises.count * 3 // 每组3分钟估算
    }

    private func calculateEstimatedCalories() -> Int {
        return exercises.count * 50 // 每组50卡路里估算
    }
}

// 使用示例
let workoutPlan = WorkoutPlanBuilder()
    .setName("力量训练")
    .setDescription("上肢力量训练计划")
    .setCategory(.upperBody)
    .setDifficulty(.intermediate)
    .addExercise(.benchPress, reps: 12, weight: 20)
    .addExercise(.shoulderPress, reps: 10, weight: 15)
    .build()
```

### 7. 装饰器模式 (Decorator Pattern)

#### 模式定义
动态地给对象添加一些额外的职责，就增加功能来说，装饰器模式相比生成子类更为灵活。

#### 在 Fit 应用中的实现

**练习功能装饰器**
```swift
protocol Exercise {
    var name: String { get }
    var baseCalories: Int { get }
    func perform() -> String
}

class BasicExercise: Exercise {
    let name: String
    let baseCalories: Int

    init(name: String, baseCalories: Int) {
        self.name = name
        self.baseCalories = baseCalories
    }

    func perform() -> String {
        return "执行 \(name)"
    }
}

class ExerciseDecorator: Exercise {
    let wrappedExercise: Exercise

    init(wrappedExercise: Exercise) {
        self.wrappedExercise = wrappedExercise
    }

    var name: String {
        return wrappedExercise.name
    }

    var baseCalories: Int {
        return wrappedExercise.baseCalories
    }

    func perform() -> String {
        return wrappedExercise.perform()
    }
}

class WeightedExerciseDecorator: ExerciseDecorator {
    let weight: Double

    init(wrappedExercise: Exercise, weight: Double) {
        self.weight = weight
        super.init(wrappedExercise: wrappedExercise)
    }

    override var baseCalories: Int {
        return Int(wrappedExercise.baseCalories * (1 + weight / 100))
    }

    override func perform() -> String {
        return "\(wrappedExercise.perform())，重量: \(weight)kg"
    }
}

class TimedExerciseDecorator: ExerciseDecorator {
    let duration: Int

    init(wrappedExercise: Exercise, duration: Int) {
        self.duration = duration
        super.init(wrappedExercise: wrappedExercise)
    }

    override func perform() -> String {
        return "\(wrappedExercise.perform())，时长: \(duration)秒"
    }
}
```

### 8. 命令模式 (Command Pattern)

#### 模式定义
将请求封装成对象，以便使用不同的请求、队列或者日志来参数化其他对象。

#### 在 Fit 应用中的实现

**训练命令系统**
```swift
protocol WorkoutCommand {
    func execute()
    func undo()
}

class StartExerciseCommand: WorkoutCommand {
    private let workoutViewModel: WorkoutViewModel

    init(workoutViewModel: WorkoutViewModel) {
        self.workoutViewModel = workoutViewModel
    }

    func execute() {
        workoutViewModel.startExercise()
    }

    func undo() {
        workoutViewModel.pauseExercise()
    }
}

class CompleteSetCommand: WorkoutCommand {
    private let workoutViewModel: WorkoutViewModel
    private let reps: Int
    private let weight: Double

    init(workoutViewModel: WorkoutViewModel, reps: Int, weight: Double) {
        self.workoutViewModel = workoutViewModel
        self.reps = reps
        self.weight = weight
    }

    func execute() {
        workoutViewModel.completeExerciseWith(actualReps: reps, actualWeight: weight)
    }

    func undo() {
        // 实现撤销逻辑
    }
}

class WorkoutInvoker {
    private var commandHistory: [WorkoutCommand] = []

    func executeCommand(_ command: WorkoutCommand) {
        command.execute()
        commandHistory.append(command)
    }

    func undoLastCommand() {
        if let lastCommand = commandHistory.popLast() {
            lastCommand.undo()
        }
    }
}
```

### 9. 状态模式 (State Pattern)

#### 模式定义
允许对象在内部状态改变时改变它的行为，对象看起来似乎修改了它的类。

#### 在 Fit 应用中的实现

**训练状态管理**
```swift
protocol WorkoutState {
    func startExercise(in context: WorkoutContext)
    func pauseExercise(in context: WorkoutContext)
    func completeExercise(in context: WorkoutContext)
    func canStartNextExercise() -> Bool
}

class WorkoutContext {
    private var state: WorkoutState = NotStartedState()
    weak var viewModel: WorkoutViewModel?

    func setState(_ state: WorkoutState) {
        self.state = state
    }

    func startExercise() {
        state.startExercise(in: self)
    }

    func pauseExercise() {
        state.pauseExercise(in: self)
    }

    func completeExercise() {
        state.completeExercise(in: self)
    }
}

class NotStartedState: WorkoutState {
    func startExercise(in context: WorkoutContext) {
        context.setState(.inProgress)
        context.viewModel?.startExercise()
    }

    func pauseExercise(in context: WorkoutContext) {
        // 未开始状态不能暂停
    }

    func completeExercise(in context: WorkoutContext) {
        // 未开始状态不能完成
    }

    func canStartNextExercise() -> Bool {
        return true
    }
}

class InProgressState: WorkoutState {
    func startExercise(in context: WorkoutContext) {
        // 已经在运行中
    }

    func pauseExercise(in context: WorkoutContext) {
        context.setState(.paused)
        context.viewModel?.pauseExercise()
    }

    func completeExercise(in context: WorkoutContext) {
        context.setState(.completed)
        context.viewModel?.completeExercise()
    }

    func canStartNextExercise() -> Bool {
        return false
    }
}
```

## 设计模式的优势总结

### 1. 代码组织
- **模块化**: 每个模式都有明确的职责边界
- **可读性**: 代码结构清晰，易于理解和维护
- **可扩展性**: 新功能可以通过扩展现有模式来实现

### 2. 测试友好
- **依赖注入**: 便于创建测试替身
- **单一职责**: 每个组件可以独立测试
- **接口抽象**: 便于创建模拟对象

### 3. 性能优化
- **懒加载**: 单例模式支持延迟初始化
- **对象复用**: 工厂模式支持对象池
- **内存管理**: 观察者模式避免内存泄漏

## 最佳实践建议

### 1. 模式选择
- **避免过度设计**: 根据实际需求选择合适的设计模式
- **保持简单**: 优先使用简单的解决方案
- **考虑未来**: 为可能的扩展预留接口

### 2. 实现规范
- **接口设计**: 保持接口的稳定性和向后兼容性
- **错误处理**: 在模式中集成适当的错误处理机制
- **文档完善**: 为复杂的模式实现提供详细文档

### 3. 性能考虑
- **避免过度抽象**: 不要为了使用模式而使用模式
- **内存管理**: 注意循环引用和内存泄漏问题
- **异步处理**: 在适当的地方使用异步模式
